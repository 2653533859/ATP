# 命令、投递与资源身份契约

本文是 N1.1 的设计交付。命令身份服务和资源 UUID 属 N1.2；持久投递器、执行端去重和恢复属于 N1.3–N1.6，须分别实现及验收。

同日 N1.4 已接入手动套件消息的永久首次接受记录、UUID/参数核对、条件启动与套件租约 UUID，见 [执行端实现](suite-delivery-development-2026-10-08.md)。接受后退出不自动重新接受；实际去重/失联验收及完整恢复仍开放，其他执行入口未扩展为全域接受机制。

同日 N1.5 已接入两种模式共用的套件/计划状态说明、条件协作取消及子归属记录，见 [恢复实现](group-recovery-development-2026-10-08.md)。查询不产生重投，取消不强杀外部动作，未知结果不清除接受凭据。实际取消/重启与双模式异常证据仍待 N1.6。

## 1. 三类状态独立

| 记录 | 含义 | 约定 |
| --- | --- | --- |
| 命令 | 用户的一个确认请求及其业务结果 | 用户+command_id 唯一，绑定项目、动作、请求哈希和结果资源身份；受理不等于运行通过 |
| 投递意图 | 已提交运行需要交给执行器的持久事实 | 后续与运行/命令同事务保存；记录目标模式、任务/队列、加密参数、领取/尝试和故障摘要 |
| 运行 | 实际执行的业务状态与证据 | 沿用各运行类型状态机/租约；命令重放读取原运行，投递器不能据 pending 就假定从未开始 |

未来投递生命周期：待投递→领取→已接受；可重试失败进入有界重试，无法确认接受结果进入“应答未知”。达到限制、资源删除、身份变化或无法验证副作用时进入明确的“恢复受阻/需人工核对”，不伪造运行成功。

## 2. 命令受理与重放

1. API 每次先校验当前用户和项目权限，包括重复请求；命令编号不构成授权。
2. 既有客户端可以省略 command_id。需要重复提交保护的动作传入稳定编号；网络重试保留编号与内容，新动作使用新编号。
3. 相同编号且项目/动作/请求哈希一致时，只返回已记录资源；不得创建替代资源或再次执行。
4. 内容、项目或动作不同返回 409。资源删除、身份变化或旧命令缺少可靠身份也返回 409，并提示核对记录。
5. 并发命令由数据库唯一约束裁决；失败事务回滚后重新查询获胜记录，使用同一校验服务。捕获用户/项目 ID，避免回滚后访问过期认证 ORM 对象。

请求哈希来自服务端规范化后的业务输入，排除 command_id；不在命令记录保存明文输入。运行套件请求同时绑定套件内部身份，防止同整数 ID 的新套件被误认为原目标。

## 3. 资源身份与历史记录

- `TestSuite.identity_token` 和 `SuiteRun.identity_token` 是内部随机 UUID；新资源有新身份，复制/重建不沿用旧身份。
- `HermesAction.resource_identity` 保存结果身份，与整数 resource_id 一起核对；同时核对项目。该字段不能由 API 更新资源时随意修改。
- SQLite 版本 8 与 Alembic 0076 为已有套件/运行生成身份；旧命令保持空身份。只根据迁移时当前整数 ID 回填旧命令无法证明原资源，故不回填。
- 历史查询返回 `available/missing/replaced/unverified`，仅 available 返回当前资源运行状态。前端区分已删除/变化与历史待核对。
- 服务器按仓库 PostgreSQL 16 基线保留数据库 UUID 默认值，旧写入者在滚动更新时也获得新身份；旧命令仍为空身份，必须核对。服务器升级须迁移门和一致候选一起交付，混跑行为另做目标环境验收。

## 4. 投递与执行保护的实施约束

1. 后续运行、命令和投递意图使用同一个业务数据库事务，提交后才允许发布消息。
2. 投递器须可重复扫描、领取有期限、故障有摘要；读取状态和重新投递分开。参数沿用加密配置，日志/审计不输出凭据。
3. 本地 SQLite 队列与服务器 Celery 分别接入相同契约；保留现有队列路由和单机串行策略。
4. 消息可重复交付，执行端依据运行身份及领取/租约去重。任务 ID 相同本身不能替代业务去重。
5. 已开始但失联的操作可能有外部副作用，不能因租约过期盲目重跑；恢复保留已知终态，未知结果提示核对。
6. 套件/计划的子执行必须遵循父子身份和状态规则；本地父任务直接串行执行子任务，不能占住唯一队列线程等待子队列任务。

## 5. 取消与验收边界

取消请求、投递状态和运行终态分别呈现。排队取消需阻止之后业务启动；运行中取消按执行器边界生效；结果未知时保留核对信息。具体 SuiteRun 取消表示和恢复接口由 N1.5 收口。

N1.6 的两侧验收覆盖：重复确认、请求冲突、资源删除/编号复用、旧命令、提交后中断、投递应答丢失、重复消息、并发领取、开始后失联、父子取消和重启。测试/业务结果绑定实际候选，不继承设计文档结论。
