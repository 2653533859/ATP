# 产品导航与能力扩展开发计划（2026-08-24）

> 状态：导航信息架构已按参考导航完成基线设计；N0 导航壳、N1 工作台与任务中心、N2.1/N2.2 内部缺陷与失败证据闭环、N2.3 报告中心已完成本地实现、审查和回归，均待真实环境验收；下一入口为 N2.4 用例评审工作台。
> 目标：将现有 ATP 平台从“按已实现页面分组”调整为参考导航中的“工作台、测试能力、测试资产、智能中枢、系统”五层产品导航，并按模块逐步补齐统一入口与业务闭环。

> 使用方式：本文件是本轮导航重构的主计划。每个模块完成后必须依次完成“实现 → 测试 → 代码审查 → 修复 → 文档/记忆同步 → 提交推送”，并在下方实施记录和 `Task.md` 中更新同一状态。未完成联调的功能只能标记为“已实现，待环境验收”。

## 1. 当前基线

当前导航实现位于 `frontend/src/layouts/MainLayout.vue`，路由实现位于 `frontend/src/router/index.ts`。现有能力已经覆盖项目、用例、套件、计划、运行记录、Web/Android、性能、AI、数据集、Mock、环境和系统配置，但仍存在以下结构问题：

- 页面按历史开发顺序分散在“测试设计、测试资产、执行中心、Android 专项、平台配置”等菜单中。
- 没有独立的“我的待办”和“任务中心”，失败任务、待评审用例、逾期计划、异常设备不能统一处理。
- 缺陷、报告和评审已有部分能力，但入口和数据流没有形成测试资产闭环。
- API、APP、UI、性能和 AI 能力已有基础实现，但缺少面向用户的一站式工作台。
- Hermes 助手、知识中枢、需求与用例追踪、远程工具箱尚未形成独立模块。

本轮参考导航的对齐原则：

- **工作台**只放用户每天需要进入的首页、待办、项目中心和任务中心，不承载具体测试配置。
- **测试能力**按测试方式组织：接口测试、APP 自动化、UI 自动化、性能测试和 AI 智能测试；每个入口最终都应覆盖配置、执行、观察和结果。
- **测试资产**按可复用、可评审、可追踪的产物组织：测试用例、测试计划、缺陷管理、测试报告和用例评审。
- **智能中枢**只放跨模块的 AI/知识能力：Hermes 助手、需求与用例生成、知识中枢；模型、密钥和调用审计仍属于系统配置。
- **系统**只放平台运行和治理能力：远程工具箱、配置中心以及存储、通知、用户、审计等管理页面，不再把测试业务页面全部堆在系统管理下。
- 旧 URL、旧 API 和已有领域页面保持兼容；页面迁移优先调整入口和上下文，避免为了菜单重构重复实现执行器。

本路线不删除既有页面；旧 URL 和 API 保持兼容，新工作台优先复用现有服务和组件，避免重复实现执行器。

## 5. 跟踪规则

- 代码完成但未联调：标记为“已实现，待环境验收”。
- 页面完成但后端/Worker 不支持：标记为“部分实现”，记录具体阻塞点。
- 每项完成内容至少记录一个测试文件、运行命令或外部验收证据。
- 新增模型必须有 Alembic 迁移；新增敏感配置不得写入文档、日志或报告。
- 每完成一个阶段，先做代码审查和回归，再更新 `Task.md`、`MEMORY.md` 与本计划状态。
