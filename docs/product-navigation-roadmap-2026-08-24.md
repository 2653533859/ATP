# 产品导航与能力扩展开发计划（2026-08-24）

> 状态：N0 基础导航已实现，项目选择器、动态徽标和业务工作台仍按后续阶段推进。
> 目标：将现有 ATP 平台从“按已实现页面分组”调整为“工作台、测试能力、测试资产、智能中枢、系统”五层产品导航，并补齐对应的统一入口与业务闭环。

## 1. 当前基线

当前导航实现位于 `frontend/src/layouts/MainLayout.vue`，路由实现位于 `frontend/src/router/index.ts`。现有能力已经覆盖项目、用例、套件、计划、运行记录、Web/Android、性能、AI、数据集、Mock、环境和系统配置，但仍存在以下结构问题：

- 页面按历史开发顺序分散在“测试设计、测试资产、执行中心、Android 专项、平台配置”等菜单中。
- 没有独立的“我的待办”和“任务中心”，失败任务、待评审用例、逾期计划、异常设备不能统一处理。
- 缺陷、报告和评审已有部分能力，但入口和数据流没有形成测试资产闭环。
- API、APP、UI、性能和 AI 能力已有基础实现，但缺少面向用户的一站式工作台。
- Hermes 助手、知识中枢、需求与用例追踪、远程工具箱尚未形成独立模块。

本路线不删除既有页面；旧 URL 和 API 保持兼容，新工作台优先复用现有服务和组件，避免重复实现执行器。

## 3. 分阶段实施计划

### 阶段 N0：导航壳与信息架构（P0，基础完成）

目标：先完成导航和路由基础，不重复开发业务能力。

- [x] 重构 `MainLayout.vue` 为五个目标分组，并统一图标、标题、展开状态和权限控制。
- [x] 通过路由 `meta` 完成能力入口注册，声明标题、说明、角色和已有入口；旧路由仍由原页面承载。
- [~] 已增加项目上下文徽标和统一页面标题规则；项目选择器、面包屑和动态菜单徽标数据由 N1 工作台聚合补齐。
- [x] 为未实现模块提供明确的功能占位页和路线说明，避免点击后无响应或空白页面。
- [x] 保留 `/cases`、`/runs`、`/plans`、`/system/performance`、Android 专项等既有 URL，新增工作台入口以跳转或嵌入已有页面。
- [x] 增加导航路由注册回归测试，并修复详情/项目子路由的菜单选中兼容。

验收（基础导航）：登录后可以按目标五层导航找到所有现有功能；不同角色只能看到有权限的入口；旧链接仍能打开原页面。项目选择器、动态徽标和聚合待办在 N1 验收。

### 阶段 N1：工作台与任务中心（P0）

- [ ] 新增“我的待办”聚合 API 和页面，汇总待评审用例、失败运行、逾期计划、未处理缺陷和设备异常。
- [ ] 新增“任务中心”页面，统一展示 Case、Suite、Plan、Android 和 Performance 任务。
- [ ] 增加统一状态、进度、创建人、项目、执行节点和最近事件字段。
- [ ] 支持重试、终止、批量执行、失败重跑、定时执行和跳转详情。
- [ ] 通过 WebSocket 或轮询统一刷新任务状态，避免每个页面单独实现状态逻辑。

验收：用户可以从一个页面找到所有待处理和执行中的任务，并完成重试、终止和查看结果。

### 阶段 N2：测试资产闭环（P1）

- [ ] 新增内部缺陷模型、创建、分派、状态流转、优先级、严重程度和重复识别。
- [ ] 将失败运行、截图、日志、Trace、用例和缺陷建立双向关联。
- [ ] 新增独立测试报告中心，支持项目筛选、历史趋势、两次运行对比、覆盖率和质量评分。
- [ ] 将现有用例评审能力提取为独立页面，支持待评审列表、批量通过/驳回、评论和评审记录。
- [ ] 保持 Jira、禅道、GitHub、GitLab 等外部缺陷集成兼容。

验收：从失败运行可以创建缺陷，从缺陷可以回到运行和用例；报告可以按项目查看趋势；评审过程可追溯。

### 阶段 N3：测试能力工作台（P1）

- [ ] API 工作台：请求编辑、环境变量、数据集、认证、断言、变量提取、依赖编排、登录态复用、OpenAPI/Postman 导入。
- [ ] APP 工作台：设备池、设备预约、APK 选择、投屏、录制、回放、日志、性能数据和兼容性矩阵。
- [ ] UI 工作台：Playwright、浏览器录制、低代码、元素库、页面对象、视觉基线、Trace、网络日志和定位器修复。
- [ ] 性能工作台：统一压测场景、k6/Locust/JMeter/gRPC、节点、资源采样、基线和报告。
- [ ] 每个工作台复用现有执行器和 API，不在前端重新实现执行逻辑。

验收：用户从测试能力菜单进入后，可以在同一工作台完成配置、执行、观察和查看报告。

### 阶段 N4：智能中枢（P1/P2）

- [ ] 新增 AI 智能测试中心，统一 AI 用例、数据、Mock、诊断、自愈、覆盖率缺口和修复建议。
- [ ] 新增 Hermes 助手，支持查询失败任务、解释错误、生成测试计划、生成用例和汇总质量指标。
- [ ] 增加需求解析、验收标准生成、需求—用例关联和需求变更影响分析。
- [ ] 新增知识中枢，统一搜索测试规范、历史缺陷、解决方案、运行手册和项目经验。
- [ ] 保留人工确认、权限、调用限额、审计和敏感信息脱敏边界。

验收：AI 生成内容默认是可编辑草稿；Hermes 的查询和建议可追溯；知识搜索结果包含来源和项目权限边界。

### 阶段 N5：远程工具箱与配置中心（P1/P2）

- [ ] 新增远程工具箱，统一检查 Worker、Redis、MinIO、PostgreSQL、ADB、浏览器节点和性能节点。
- [ ] 支持诊断结果、检查时间、失败原因和安全导出，不输出密码、Token 或密钥。
- [ ] 将启动配置、环境、全局变量、AI、存储、通知和性能配置归入统一配置中心。
- [ ] 增加配置差异、变更审计、影响提示和可控回滚。

验收：管理员可以从一个入口判断服务是否可用，知道失败原因，并能追溯配置变更。

### 阶段 N6：质量收口与发布（P0）

- [ ] 为新增路由、权限、聚合 API、迁移和关键交互补充后端/前端回归。
- [ ] 更新能力矩阵、用户手册、导航说明、Task、MEMORY 和实施日志。
- [ ] 完成 type-check、生产构建、Vitest、后端回归、独立测试扫描和必要 E2E。

## 4. 推荐执行顺序

```text
N0 导航壳
  -> N1 工作台与任务中心
  -> N2 测试资产闭环
  -> N3 API/APP/UI/性能工作台
  -> N4 AI 与智能中枢
  -> N5 远程工具箱与配置中心
  -> N6 质量收口与发布
```

预计工作量：单人约 26～38 个开发人日。N0、N1 完成后再扩展业务模块，避免继续增加分散入口。

## 5. 跟踪规则

- 代码完成但未联调：标记为“已实现，待环境验收”。
- 页面完成但后端/Worker 不支持：标记为“部分实现”，记录具体阻塞点。
- 每项完成内容至少记录一个测试文件、运行命令或外部验收证据。
- 新增模型必须有 Alembic 迁移；新增敏感配置不得写入文档、日志或报告。
- 每完成一个阶段，先做代码审查和回归，再更新 `Task.md`、`MEMORY.md` 与本计划状态。
