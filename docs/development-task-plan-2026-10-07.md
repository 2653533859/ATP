# ATP 新任务计划（2026-10-07）

> 状态：计划已建立，开发任务待收口。承接 [整体路线分析](project-development-roadmap-summary-2026-10-07.md)，作为本日期起剩余工作的统一任务入口。旧计划保留阶段设计、专项标准和历史证据，新增进度按本文编号维护。

## 1. 目标与范围

本轮目标：让 Windows 单用户、单项目版本可靠运行、方便备份和转移，同时保证 Linux 服务器模式的共同业务能力继续正常使用。

| 维度 | Windows 本地 | Linux 服务器 |
| --- | --- | --- |
| 数据与文件 | SQLite、本地目录 | PostgreSQL、MinIO |
| 任务执行 | SQLite 持久队列，组任务串行 | Redis/Celery，既有 Worker 路由 |
| 使用范围 | API、Web、Android、手动套件/计划及已开放的本地扩展 | 现有多用户、多项目、权限、调度与业务能力 |
| 交付目标 | 明确依赖的目录交付、启动、升级、备份和异机恢复 | 单节点 K3s 同版本发布、回滚与持续观测 |
| 模式切换 | 使用独立本地入口、账号、配置和数据 | 使用独立服务器入口、账号、配置和数据 |

两套数据和密钥独立。核心本地流程应在不连接 Linux 的情况下使用；外部接口、联网模型和 Android 真机分别需要对应网络、模型配置和设备。

多节点高可用、跨主机 MinIO 灾备、本地 iOS、外部通知/缺陷供应商正式兼容、自动双向数据同步列为后续范围。本地 Cron/Webhook、性能远程分片暂不纳入本轮。

## 5. 下一批实际开发

首批安排：

1. **N0.1–N0.3**：列出当前支持矩阵、整理改动并同步操作口径。
2. **N1.1–N1.2**：确定状态/资源身份契约，抽取命令服务，修复旧命令返回后建同编号资源的风险。

后续按 N2、N3、N4 推进。开发过程中每个工作包先完成实现和审查，再按实际授权开展检查/测试与业务验收；计划建立阶段仅交付文档，之后的实际实施结果见进度记录。
