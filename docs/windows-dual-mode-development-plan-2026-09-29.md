# Windows 本地／服务器双模式开发计划（2026-09-29）

> 状态：实施中。本文是双模式切换和 Windows 单用户单项目本地版的执行表；`windows-standalone.md` 记录当前操作方式。完成状态以真实业务闭环为准，不以页面打开或进程健康代替。

## 1. 目标与边界

| 项目 | Windows 本地模式 | 服务器模式 |
| --- | --- | --- |
| 使用者与项目 | 一个用户、一个默认项目；后台仍保留 `Project` 数据模型 | 保留现有账号、项目、权限和服务器业务能力 |
| 数据库 | 本机 SQLite，独立版本迁移 | 现有 PostgreSQL 与 Alembic |
| 文件 | 本机数据目录中的对象文件 | 现有 MinIO |
| 手动执行 | 单机持久任务队列；不依赖 Redis/Celery | 现有 Celery/Redis Worker 与队列路由 |
| 界面 | 只展示已适配并验收的本地能力 | 保留现有功能与入口 |
| 数据关系 | 与服务器不自动同步；本地账号、密钥、运行记录和附件独立 | 不读取或改写本地数据目录 |

首版本地验收范围：登录、默认项目、用例创建/编辑、API 与 Web 用例手动执行、执行结果/步骤、常用报告及附件上传/下载。Android/iOS 专用队列、分布式执行、性能节点、录制、定时计划和依赖 Redis 的 AI 功能暂不进入本地首版验收；服务器模式继续保留这些既有能力。不能仅隐藏菜单，后端也要对未支持的本地入口返回明确的能力错误。

## 2. 切换约定

1. 开发期允许两个模式同时运行：服务器页面沿用 `127.0.0.1:5173`（代理到服务器），本地页面沿用 `127.0.0.1:5174`（代理到本机 `8001`）。最终 Windows 启动入口统一提供 `local`、`server`、`status` 和 `open`，切换只改变打开的模式，不在正在进行的请求中热替换 API 目标。
2. 两套页面即使端口不同也共享 `127.0.0.1` 的 Cookie 作用域。服务器保留现有认证 Cookie 名称，本地使用独立名称，并同步调整本地 HTTP 认证、刷新、退出和 WebSocket；确认浏览器持久状态按端口隔离。切换后分别保持各自登录态，退出一个模式不得清除另一个模式的会话。
3. 页面模式标识以当前后端的只读运行信息为准，不能只依赖 Vite 构建变量。模式、数据库类型和存储类型必须可见；发现页面模式与 API 模式不一致时阻止业务操作并提示重新打开正确入口。
4. 本地配置只从专用档案加载。配置校验必须确保本地模式不会意外连接服务器的 PostgreSQL、Redis、MinIO 或 Celery；服务器配置和部署流程保持原样。两个模式都只监听其预期地址，且只使用自己的账号、密钥、数据库和文件。

## 4. 每项合入门槛

1. 每个跨模式改动分别记录本地 SQLite 和服务器 PostgreSQL 的结果；涉及附件同时检查本地目录与 MinIO，涉及任务同时检查本地执行器与 Celery。只通过其中一侧，不标记 `[x]`。
2. 数据模型变更必须同时提供 PostgreSQL Alembic 与 SQLite 升级路径，并验证从已有本地数据升级；`create_all` 只用于新库初始化。
3. 模式切换检查至少覆盖：各自登录、同时打开两套页面、切换后 Cookie 与浏览器状态不串用、错误 API 目标拒绝、服务器断连时本地仍可用、重启后各自数据不变化。
4. 本地备份必须包含 SQLite、对象文件、配置和密钥，停止写入或使用一致性快照，并校验恢复结果；备份不写入仓库。服务器现有备份流程继续独立。
5. 更新 `Task.md`、本地使用文档及发布范围说明；未适配功能清楚标注，不能用启动成功替代业务验收。完成代码审查和修复后，按当次任务要求提交与推送。

## 5. 当前事实与近期顺序

- 当前本地模式支持 `8001/5174` 开发入口和仅由 `8001` 提供页面/API 的静态入口。真实 API、Web 用例均已完成创建、批准、执行和步骤读取；API 请求文件上传/签名下载、Web 运行取消、排队任务重启继续、含执行数据的报告总览/趋势/CSV 也通过。异机移机、服务器双会话与完整附件矩阵仍待验收。阶段成果位于 `codex/windows-local-dual-mode` 分支。
- M0 的可复现起点见 [`evidence/windows-dual-mode-baseline-2026-09-29.md`](evidence/windows-dual-mode-baseline-2026-09-29.md)；本地认证现已完成一条定向检查，不能替代首版业务验收。
- 本地配置已改为只读取专用档案允许的键，不加载根 `.env`；本地认证 Cookie 使用独立名称。`windows-mode.ps1` 已能报告本地和服务器页面 ready，并按模式打开入口。服务器现有后端仍未提供 `/runtime`，页面用旧版服务器兼容路径，正式双向会话切换和部署身份尚待验收。
- SQLite 已有版本 4 升级路径、单调运行 ID 和单机持久队列；运行中断的任务不会自动重放，需用户检查副作用后重试。停机备份在独立目录恢复后通过清单校验与 SQLite `integrity_check=ok`；异机恢复仍待演练。
- 当前工作区非集成后端全量回归 2778 passed/2 skipped、覆盖率 82.00% 达门槛，前端本地静态构建通过；重启后 `8001` 本地入口返回正确运行身份和登录页。复查时 `5173` 服务器页面已不可达，因此现阶段仍缺实际服务器业务及双会话切换证据。
- 推荐执行顺序：M0 → M1 与 Cookie 隔离 → M2 → M3/M4 → M5/M6 → M7 → M8。服务器模式在每一步都保留可启动和可回退状态。
