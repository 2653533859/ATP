# ATP 团队轻量版快速起步与 AI 协同实战指南 (Team AI Edition)

**适用对象**: 3~15 人研发与测试团队
**核心特性**: 纯轻量化运行、UI 菜单去噪聚焦、RAG 知识库绑定、Hermes 对话式智能体、一键 AI 生成用例、AI 失败根因诊断。

---

## 1. 架构精简与资源要求

针对中小团队日常敏捷迭代需求，本专版全面移除了高阶全链路影子压测发压集群、混沌故障注入探针与多云容灾调度器，保留纯粹的**用例资产管理 + 跨端测试执行 + AI 智能中枢**。

| 对比维度 | 全量企业版 | 团队轻量版 (当前分支) |
|---|---|---|
| **推荐服务器规格** | 4C8G ~ 8C16G | **2C4G 即可流畅运行** |
| **整体常驻内存** | 约 6GB ~ 8GB | **约 1.5GB ~ 2.5GB** |
| **容器组件数** | 12+ 个（含 Jaeger/Prometheus/Grafana） | **7 个核心容器** (Postgres, Redis, MinIO, Backend, Worker, Beat, Frontend) |
| **侧边栏导航** | 20+ 个复杂工作台 | **4 大核心聚焦板块** (工作台、能力台、测试资产、智能中枢) |

## 2. 极速一键部署 (Docker Compose)

### 步骤 1: 准备环境变量
在项目根目录下，直接使用预置好的 `.env.lite`：
```bash
# 可根据需要修改 .env.lite 中的管理员初始密码或数据库密码
cat .env.lite
```

### 步骤 2: 一键拉起服务
执行如下命令启动全套轻量化容器：
```bash
docker compose -f docker-compose.lite.yml --env-file .env.lite up -d
```

### 步骤 3: 访问系统
* **前端 Web 界面**: `http://<你的服务器IP>:80`（或本地 `http://localhost:80`）
* **初始管理员账号**: `admin`
* **初始管理员密码**: `Admin@123456`
* **对象存储控制台**: `http://<你的服务器IP>:9001` (账号 `minioadmin`，密码 `minio_team_password_2026`)

## 3. 核心功能实操工作流

### 工作流 1：配置大模型 API Key（连接大脑）

支持接入 **DeepSeek、通义千问 (Qwen)、OpenAI** 等任意主流大模型：
1. 使用管理员登录系统，点击左侧菜单 **【配置中心】**；
2. 在配置中心选择 **【大模型配置 (AI LLM)】** 模块，点击“新建配置”；
3. 选择提供商（推荐选择 `DeepSeek` 或 `通义千问 Qwen-2.5`，调用成本极低且中文与代码能力强劲）；
4. 填入 API Key 与 Base URL（如 `https://api.deepseek.com`），勾选“设为团队默认模型”并保存。

---

### 工作流 2：建立业务 RAG 知识库（消除业务认知偏差）

将团队的产品需求文档（PRD）、接口规范或业务规则录入知识库，使 AI 具备团队专属业务上下文：
1. 点击左侧菜单 **【智能中枢 ➡️ 知识中枢】** (`/knowledge`)；
2. 点击“新建知识库”，例如输入 `电商支付与订单系统规范`；
3. 点击“上传文档”，支持 Markdown、PDF 或纯文本接口说明；
4. 系统将在后台自动进行**文本语义切片（Chunks）与索引**，AI 智能体即可在对话和生成用例时实时关联召回。

---

### 工作流 3：一键 AI 生成测试用例（用例自动生成）

无需人工一条条编写测试步骤与断言，利用 AI 批量生成测试用例：

#### 方式 A：在用例管理页直接呼出
1. 进入 **【测试资产 ➡️ 用例管理】**；
2. 点击列表顶部的 **“AI 一键生成用例”** 按钮；
3. 输入你的业务意图或直接粘贴接口的 cURL / Swagger JSON；
4. 选择参考知识库，点击“生成”，系统自动解析并输出带有前置条件、请求参数、多级状态码与响应体断言的标准化用例草稿，点击“确认入库”即可。

#### 方式 B：通过 Hermes 对话助手自然语言交互
1. 进入 **【智能中枢 ➡️ Hermes 助手】** (`/hermes`)；
2. 在对话框直接输入自然语言，例如：
   > *"根据退款接口规范，生成一套包含全额退款成功、余额不足拦截、重复退款幂等性校验的接口测试用例。"*
3. Hermes 将调用意图合成引擎，右侧面板即时呈现生成的用例草稿与步骤预览，点击一键即可保存至用例库并编排进执行套件。

---

### 工作流 4：用例执行与 AI 失败根因深度诊断（故障秒级定位）

当自动化测试运行失败时，无需人工去一层层看成百上千行的日志堆栈：
1. 在 **【测试资产 ➡️ 测试报告】** 中打开任意一次包含失败步骤的报告详情；
2. 找到红色的失败步骤，点击步骤右侧的 **“🤖 AI 根因诊断”** 图标；
3. 系统将自动打包：
   - 步骤实际请求与响应体（或 UI 错误截图与 DOM 快照）
   - 失败断言详情（Expected vs Actual）
   - 异常堆栈追踪（Traceback）
4. 调用大模型进行深度语义推理，秒级输出**结构化根因分析报告**：
   - **根本原因分类**：清晰判断是 `服务端缺陷 (500 Internal Error)`、`脏数据冲突` 还是 `前端定位符漂移`；
   - **修复建议**：提供立即可执行的代码或用例参数修复建议；
   - 若属于前端 UI 定位符失效，还支持一键触发 **智能自愈（Self-Healing）** 自动修补用例。

## 4. 日常维护与命令参考

```bash
# 查看所有容器运行状态
docker compose -f docker-compose.lite.yml ps

# 查看后端实时日志
docker compose -f docker-compose.lite.yml logs -f backend

# 查看 Celery 异步任务与 AI 执行日志
docker compose -f docker-compose.lite.yml logs -f worker

# 优雅停止所有容器
docker compose -f docker-compose.lite.yml down

# 彻底清理并重启 (保留数据库数据)
docker compose -f docker-compose.lite.yml restart
```
