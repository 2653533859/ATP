## 1. 版本概述 (Executive Summary)

ATP v2.6.0 是在 v2.5.0 双模式（Windows 本地轻量与 Linux 现场集群）全面收口后推出的**重大功能演化与企业级生态集成版本**。

本版本历经 4 大阶段共 12 项重大特性演进，全面落地了 **Hermes AI 标准 Model Context Protocol（MCP）Server 与多模态视觉自愈**、**AutoDroid 远程反向隧道真机池化调度与故障录屏对齐**、**云原生 Kubernetes 弹性算力分片与 Prometheus 饱和度熔断保护**，以及 **企业微信/钉钉/飞书三端交互式富卡片与 Jira/禅道双向缺陷生命周期状态机同步**。

## 2. 核心特性发布清单 (Key Highlights by Phase)

### Phase 1：Hermes AI 契约与低代码多模态能力 (AI & Tool Protocol)

- **P1.1 ATP 核心工具 MCP Server 标准化暴露**：
  - 支持标准 Model Context Protocol（MCP v1 / 2024-11-05）规范；
  - 提供 JSON-RPC 2.0 / Stdio（`python -m app.mcp`）与 HTTP 端点（`POST /api/v1/mcp/rpc`）双模接入；
  - 对外标准化开放 7 项平台核心工具：`atp_list_cases`、`atp_get_case_detail`、`atp_run_case`、`atp_get_run_status`、`atp_diagnose_failure`、`atp_create_defect`、`atp_get_project_summary`，无缝对接 Cursor、Claude Desktop、Hermes 智能体等外部 LLM 生态。
- **P1.2 多模态视觉断言与元素视觉自愈**：
  - 落地 `visual_assertion` 图像算子，基于 Pillow/Normalized RMS 图像相似度对比与模板滑动窗口物理坐标定位；
  - Web 与 Android 自动化执行器原生支持 `assert_visual_element` 断言动作；
  - 运行时定位器自愈器 `runtime_locator_healer` 接入 `attempt_visual_healing`，在 DOM / UiAutomator 选择器失效时，全自动基于 OCR 文本定位或图像模板物理坐标点击回退救活用例。
- **P1.3 双向规格同步与测试资产自动对齐**：
  - 落地 `spec_sync` 契约比对服务，深度解析 OpenAPI/Swagger 规范与既有 TestCase 的三维差异（`additions`, `modifications`, `deprecations`）；
  - 自动生成增量用例草稿（`TestCaseCreate`），开放 `/api/v1/projects/{id}/api-contracts/sync-cases` 端点，实现接口资产双向版本对齐。

---

### Phase 2：Android 真机池化调度与远程 Agent 治理 (Device Pool & Matrix)

- **P2.1 AutoDroid 远程反向隧道 Agent 注册与心跳**：
  - 基于 Schema 13 `remote_agents` 与 `remote_agent_devices` 动态绑定跨网真实真机；
  - 远程设备通过 127.0.0.1 映射端口自动同步进入中央设备池并标为 `online`，掉线或心跳超时状态自动联动收敛；
  - 支持 Agent 删除级联回收对应设备，实现企业多地真机集中管控。
- **P2.2 真机矩阵并发执行与智能租约队列**：
  - 套件维度支持 `device_matrix` 真机矩阵设备展开并发执行；
  - `acquire_available_device_from_pool` 实现动态行锁抢占空闲设备，自动跳过忙碌占用设备；
  - `handle_device_disconnection_recovery` 在真机拔线或离线时全自动释放设备租约并收敛在途执行为错误终态。
- **P2.3 Android 录屏分段与 Logcat 故障现场自动归档**：
  - 落地 `android_incident_archiver` 服务，实现标准 Logcat 时间戳（`MM-DD HH:MM:SS.mmm`）精确解析；
  - 在 Crash / ANR 异常发生时，自动在 `[T-30s, T+30s]` 时间窗口截取 MP4 视频短片段与关联日志切片；
  - 自动创建并关联 `MobileIncident` 与 `MobileRunArtifact` 实体，为缺陷排查提供现场证据。

---

### Phase 3：云原生 Kubernetes 分布式性能算力池 (Cloud-Native Distributed Performance)

- **P3.1 K8s 动态性能压测 Pod 弹性扩缩容调度**：
  - 落地 `k8s_performance_operator` 服务，基于 Kubernetes `batch/v1` Job 规范构建算力分片 Pod；
  - 自动注入 CPU/Memory 资源限制（`1000m / 1Gi`），根据并发规模（`shard_count`）自动无损切片负载；
  - 强制注入 `ttlSecondsAfterFinished: 300` 自动清理机制，压测结束 5 分钟后自动回收计算资源，杜绝孤儿 Pod 堆积。
- **P3.2 分布式性能指标实时汇总与基线比对**：
  - `aggregate_distributed_timeseries_samples` 实现跨多个 K8s Pod 的时序吞吐量（RPS/TPS）精准求和、延迟峰值分位数（Worst-case Percentile）提取与加权平均错误率计算；
  - 增强 `build_baseline_comparison` 输出自动化质量门禁判定（`verdict`: `passed` | `regression` | `improvement`），当 TPS 下降 > 15%、延迟恶化 > 20% 或错误率增加 > 2% 时自动拦截为质量劣化。
- **P3.3 多节点高可用与 Prometheus 报警规则集成**：
  - `build_prometheus_alert_rules` 声明式生成压力机与被测目标系统的 Prometheus 告警规则组；
  - `evaluate_circuit_breaker` 与 `trip_circuit_breaker_if_saturated` 在压力机 CPU/内存饱和度（>=90%）或目标过载时自动触发熔断降级与应急停机，防止集群雪崩；
  - `select_ha_performance_nodes` 实现多节点高可用调度与 Standby 备份冗余分流。

---

### Phase 4：企业级通知协同与外部缺陷平台双向同步 (Ecosystem & Integrations)

- **P4.1 企业微信 / 钉钉 / 飞书 富卡片通知模板**：
  - 落地 `rich_notification_cards` 服务，支持企业微信 `template_card` 模态卡片、钉钉 `actionCard` 单动作按钮卡片与飞书 `interactive` 交互式卡片；
  - 支持动态状态色彩徽标（绿色 `#07C160`、红色 `#FA5151`、橙色 `#FF9F00`）、大号通过率看板、耗时/TPS 横向列表，以及一键直达在线测试报告的操作按钮；
  - 支持飞书 HMAC-SHA256 签名机制与 `20261015_0080` 渠道拓展迁移。
- **P4.2 Jira / 禅道 双向缺陷生命周期状态机同步**：
  - `map_internal_to_external_status` 实现平台缺陷状态与外部 Jira / 禅道规范状态的双向对应；
  - `POST /api/v1/defects/webhook/{tracker_id}` 接收外部 Jira Issue 或禅道 Bug 状态变动回调，自动对齐平台内 `Defect.status`；
  - `POST /api/v1/defects/{id}/external-links/{link_id}/push` 提供平台缺陷状态主动推送到外部平台的正向接口。
- **P4.3 跨网络环境通知投递重试与安全审计**：
  - 精准区分瞬时网络重试与客户端不可重试错误，实现带 Jitter 抖动的指数退避重试算法；
  - 落地 `sanitize_webhook_url` 与 `sanitize_notification_config`，对企微 Key、钉钉 Token/Sign、飞书 Token 与 URL 凭证进行深度脱敏；
  - 全面打通 `write_audit_log` 审计服务，记录结构化通知投递日志与脱敏错误摘要。
