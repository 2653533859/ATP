# ATP 本次发布范围（2026-09-01）

本文是本次发布对 iOS、外部通知渠道和外部缺陷平台的统一范围决策。它只定义正式支持与发布门禁，不删除已有代码，也不把本地回归、回环服务或未执行项写成真实环境通过。

## 范围结论

| 能力 | 本次正式支持范围 | 交付状态 | 发布门禁影响 |
| --- | --- | --- | --- |
| Android | 纳入 | Karing 单设备闭环已有受控真实证据；多设备与兼容性矩阵继续作为扩展边界记录 | 不改变 P4 性能核心门禁 |
| iOS / Appium | 不纳入 | 设备、IPA、租约、Worker 和执行器代码保留为技术预览；没有 macOS/Xcode/WDA/iPhone 真实闭环 | 不阻塞本次发布，不得宣称正式支持或真实通过 |
| SMTP 邮件 | 不纳入 | 配置、发送、重试和回环 SMTP 证据保留为技术预览；没有真实供应商送达回执 | 不阻塞本次发布，不得把 `local_link_only` 写成真实送达 |
| 企业微信机器人 | 不纳入 | Webhook 适配器和配置入口保留为技术预览；没有真实供应商验收 | 不阻塞本次发布，不得宣称真实送达 |
| 钉钉机器人 | 不纳入 | Webhook、签名和配置入口保留为技术预览；没有真实供应商验收 | 不阻塞本次发布，不得宣称真实送达 |
| Jira / 禅道 | 不纳入 | 创建、去重、附件和状态同步适配器保留为技术预览；没有真实临时项目闭环 | 不阻塞本次发布，不得宣称平台兼容性通过 |
| GitHub Issues / GitLab Issues | 不纳入 | 扩展适配器保留为技术预览；没有真实临时项目闭环 | 不阻塞本次发布，不得宣称平台兼容性通过 |

## 发布与产品边界

1. “不纳入”表示不属于本次正式支持承诺和发布验收门禁，不表示代码已删除，也不表示能力已通过真实环境验收。
2. 现有 API、配置页、脚本和自动化测试可以继续保留，但发布说明、演示材料和验收结论必须标注“技术预览 / 未经目标环境验收”。
3. 本次发布不要求提供 iOS 设备、外部通知供应商或外部缺陷平台凭据；不得为了关闭范围决策而创建伪造证据或把跳过项记为通过。
4. P4 真实 Kubernetes、发布级 Prometheus 和独立 MinIO source/target 仍是当前唯一明确阻塞的核心能力门禁；P9 继续等待 P4 后绑定最终 SHA 并完成发布收口。
5. Android 多设备、生产协议目标、Web Worker 异常场景和生产运维证据继续按开发计划记录为扩展或目标环境边界，不因本范围决策自动转为通过。

## 后续重新纳入条件

任何被排除能力要进入后续正式发布，必须先更新本文件和能力矩阵，并完成对应真实环境证据：

- iOS：macOS Worker、Xcode、Appium 2/XCUITest、WebDriverAgent、签名 IPA、真实 iPhone/Simulator、媒体/日志/报告回传和清理。
- 通知：每个纳入渠道分别完成真实成功投递、失败重试、限流/超时、供应商侧结果核对和凭据清理。
- 外部缺陷平台：每个纳入平台分别完成临时项目中的创建、重复识别、附件、状态同步、权限拒绝和删除/撤销。

重新纳入时必须保存脱敏证据并重新打开对应发布门禁；现有本地测试和历史 `local_link_only` 证据不能替代。
