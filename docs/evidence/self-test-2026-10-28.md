## 失败与阻塞

1. 后端非集成整套收集约 3126 项（随后新增一项回归，收集为 3127）。首轮记录 864 项执行结果：778 通过、86 失败，之后连续 324 秒无日志进展，停止该测试进程；此轮未完成，不能按全套通过报告。原始记录为 `backend.log`、`backend-partial.json`。
2. 测试隔离存在问题。组合运行 `test_cloud_sync_api.py` 与 `test_deps_project_access.py` 时，云同步授权测试期望 403 却收到 401。鉴权依赖模块的模块级删除/重新导入，使 FastAPI 捕获的依赖与后续动态导入得到的覆盖键不一致。另有 Mock/移动专项用例在整套失败但单独运行通过。不能把此类结果直接解释为产品接口全部失效。
3. 独立迁移检查确认 `remote_agents`、`remote_agent_devices` 两个 ORM 表在 Alembic 中没有建表迁移。源码搜索也未找到这两个名称的迁移。这是服务端空库部署的 schema 缺口；本地 SQLite 自动建表的启动验证不能替代 PostgreSQL/Alembic 验收。
4. 启动生命周期测试独立运行有两项失败：配置替身缺少 `CLOUD_SYNC_ENABLED`，请求替身缺少 `headers`。真实 source backend 与冻结 backend 已完成启动验证，但测试桩仍需要同步。
5. Chrome 自动化 CDP 连接返回 HTTP 403，需要浏览器的远程调试授权；未进行 UI 点击与页面交互测试。

### API 按文件隔离对照

运行 `scripts/pytest-standalone-sweep.py backend/tests/api --jobs 4 --timeout 120`：127 个文件中 122 个通过、5 个失败。此处统计单位是文件，不是测试用例。

- `test_case_execution_guards.py`：缺失 `inject_w3c_trace_headers` 导入；文件使用了覆盖整个 tracing 模块的旧 stub。
- `test_cloud_sync_api.py`、`test_n2_1_case_lifecycle.py`：超过本次设置的单文件 120 秒上限，不能认定通过。
- `test_device_agents_api.py`：复用的 standalone 临时目录出现 Windows WinError 5；需用新临时目录对照，不能直接归为产品失败。
- `test_remote_device_connect.py`：`FakeDB` 缺少 `get` 方法，属于未适配实际调用链的测试替身。

原始结果为 `api-standalone.log`，并发与超时阈值是上述结果的一部分。

后续使用全新临时目录重跑云同步和设备代理：**11 passed，127.32 秒**。这说明云同步文件的 120 秒限制过短，设备代理原失败也未在新目录复现。随后缩小云同步测试的异步建表范围为实际使用的汇总表，并固定其 FastAPI 鉴权依赖覆盖引用，再与鉴权依赖/设备代理合并复查得到上述 28 passed。未重跑整个 127 文件扫描，因此保留首轮原始统计；其余三个文件的导入、FakeDB 和超时问题仍未解决。

自测期间修正账号与鉴权依赖测试的过时请求桩（补 `state`/`headers`），新增 API Key 修改账号资料被拒绝的回归断言，并修正云同步测试的依赖引用和建表范围。未削弱既有断言，未修改业务源码。
