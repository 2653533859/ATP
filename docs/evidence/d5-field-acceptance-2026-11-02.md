## 现场验证

- 目标为 `192.168.3.196` 的 `atp-single-node` release。Windows 本地节点原先停止，临时启动前核对 outbox 为空；验收后停止，恢复原状态。
- 现场在线节点通过云端代理读取本机项目：管理员 200，未认证 401，工程师、测试、只读角色分别 403。使用真实现有账号角色签发的短期令牌；不记录令牌或用户名。
- 向项目接口发送 8,388,608 字节的无效 JSON，返回 422，证明该请求到达本机参数校验；8,388,609 字节返回 413。再次读取项目返回 200。
- 使用临时本机对象与短期签名，8,388,608 字节通过云端下载返回 200，内容 SHA-256 与原文件一致；8,388,609 字节返回 502，响应体为空；随后读取项目仍返回 200。临时对象、签名清单和远端临时文件已清理。
- 当前线上代理把请求完整缓存在内存中，再经 Base64/WebSocket 传输；不是流式文件传输，8 MiB 为单次请求和响应上限。

## 本地代码修正与未部署边界

- 网关按流分段读取请求，累计超限时停止读取并返回 413；本地节点发现响应超过 8 MiB 时返回明确的 413，而非泛化为 502。
- `backend/tests/api/test_remote_nodes_d5.py` 独立运行 11 项通过，覆盖恰好上限、分段超限后不继续读取或转发、超限下载错误；相关文件 Ruff 检查及格式检查通过。
- 使用修改后的工作区代码临时重启 Windows 节点，并经未修改的线上云端网关复测：8,388,608 字节下载 200 且 SHA-256 一致；8,388,609 字节返回 413 和明确的大小限制信息；随后项目读取 200。临时文件清理后节点恢复停止状态。
- 此修改尚未部署到正式发布包或云端镜像。现场复测覆盖了修改后的 Windows 开发节点与原线上网关；网关分段读取的代码仅经本地定向回归验证。

## 多用户授权缺口

当前云端代理只允许管理员，Windows 节点以本机管理员身份执行代理请求，缺少节点授权的持久化、授权管理入口、云端用户/项目成员解析、可撤销的只读/读写身份映射及可追溯审计。单纯放行非管理员或按 HTTP 方法过滤会继承本机管理员权限，不能满足用户确认的权限规则。需要实现并分别验证授权、未授权、跨电脑、项目成员变化、只读绕过、写入、撤销和重启后的持久性，再进行现场验收。

## Helm 核验

- Release `atp-single-node` revision 65 为 deployed；六个 ATP Deployment 均 1/1，后端健康接口返回 200。实际后端镜像为 `registry.local/atp/backend:v2.7.1-d5-safe2`。
- `helm get values` 的显式后端 tag 仍为 `v2.7.0`，release 已保存清单也为 `v2.7.0`。仓库 `values.yaml` 的新默认值无法覆盖 `--reuse-values` 中的旧显式值；之前“已消除部署漂移”的结论不成立。
- 从当前仓库 HEAD 导出 Chart，在目标集群对 revision 65 执行 `helm upgrade ... --reuse-values --no-hooks --set-string image.backend.tag=v2.7.1-d5-safe2 --dry-run=server -o json`。渲染的 10 个资源无增删，相对已保存清单仅后端 Deployment 的容器镜像字段变化。使用 release 自身保存的 Chart 重复同一 dry-run，结果一致。
- 本次没有执行真实 Helm upgrade，revision 仍为 65，旧显式值仍然存在。上述 dry-run 是某一时点的渲染核验，不代表升级、迁移、上线或长期稳定性验收。实际升级前应针对当时的 release、Chart、值和现场 Deployment 再做漂移核验，审查 hook/迁移与回滚；不得仅依靠默认 values。
