# Android Agent M0：采集与中文输入适配层

日期：2026-11-06。续接[汽水音乐搜索验证](android-agent-m0-qishui-search-20261106.md)。

## 已实现

新增 `backend/app/services/android_agent/device_adapter.py`，用于后续受监督 M0 实验，尚未接入生产执行器、API 或桌面安装包。

- 通过已固定的 uiautomator2 3.2.1 服务调用 `dumpWindowHierarchy`，最多尝试 3 次读取；空树、无效 XML 不作为有效观察，采集前后核对前台包名。这里是采集次数及单次 RPC 超时限制，不宣称严格的整个流程墙钟时间限制。
- 对包内唯一、启用、具有有效屏幕边界的非密码 EditText 调用 `setText`，支持直接提交 Unicode 文本；不执行 shell 文本转义，不切换输入法，不用拼音坐标点击兜底。
- 写入前重新核对控件数量、前台包名，并调用由上层提供的写门禁；尚未实现生产租约协调器。字段输入是替换语义，不支持追加；当前最多 512 字符。
- 写后重新采集，验证同一唯一控件的文本精确一致。解析器新增 `text_truncated`，避免把截断后的前缀当成完整文本而错误通过。
- 固定版本的公开 `jsonrpc_call` 在 HTTP/自动化连接异常时会重启并重发。因此适配层明确使用该版本的单次底层调用，写操作不重试；发出后出错统一返回 `input_outcome_unknown`。后续协调器必须把该状态转为暂停和重新观察，不能直接重跑。
- 新增版本保护：升级 uiautomator2 后必须重新审查单次调用的语义。连接 UIAutomator 服务可能启动/安装随依赖分发的服务，本轮未执行设备安装。
