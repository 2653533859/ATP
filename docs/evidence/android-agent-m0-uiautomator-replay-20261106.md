# Android Agent M0：UIAutomator 中文输入与无模型回放现场验证

日期：2026-11-06；设备：用户重新连接的 OPPO R11（Android 9）；App：汽水音乐 `com.luna.music`。续接[适配层实现记录](android-agent-m0-adapter-20261106.md)。

## 结论与边界

本次新适配层在该设备上完成直接中文输入，并以固定步骤连续完成两轮“首页 → 搜索晴天 → 核对歌曲结果 → 返回首页”。整个本轮没有调用模型、发送截图给模型、人工逐键输入、切换输入法或使用硬编码坐标回退。

这是操作员监督下的独立设备实验脚本，不是 ATP 正式低代码执行器/TestRun 回放，不代表自然语言工作台、租约互斥、会话协调器或 M0 全部验收通过。实验门禁只核对指定设备与前台包名，没有集成生产设备租约。不能在存在并发人工/任务控制时复用此实验方式。

## 现场证据

1. ADB 重新检测到 online 设备，初始在手机桌面；显式连接已固定的 uiautomator2 3.2.1 服务，桌面结构读取成功。随后启动用户指定 App，等待实际首页标识出现。没有修改 idle 配置。
2. 首页搜索入口 `com.luna.music:id/cz=` 经新观察和唯一性检查后点击；搜索框 `com.luna.music:id/df9` 为唯一启用 EditText。
3. `AndroidDeviceAdapter.replace_text` 直接设置“晴天”，返回后重新读取并精确验证文本。首次现场输入成功。
4. 搜索建议中唯一的 `com.luna.music:id/dge` + 文本“晴天”具有可点击父节点，按语义选择器提交；没有使用键盘坐标或盲目重发 Enter。
5. 初次结果采集时仍在加载，后续观察获得真实结果。独立回放使用条件等待，最多等待 20 秒后停止；单次设备读取耗时可能使总时长略超该期限。
6. 返回首页后运行两轮固定脚本：两轮均通过输入、结果和回到首页的独立后置检查。结果页每轮额外连续采集 3 次，断言持续通过。
7. 最后截图确认已回到首页、播放按钮为暂停时的播放三角；默认输入法仍为原 SogouIME。最后 ADB 检查仍在线。

结果断言同时要求：

- 唯一搜索框文本精确等于“晴天”；
- 页面存在“综合”结果页标签；
- `com.luna.music:id/de8` 的文本等于“歌曲”；
- 至少一个独立 TextView 的文本精确等于“晴天”，排除输入框和建议条目；
- 页面不存在搜索建议条目 `com.luna.music:id/dge`。

未点击歌曲播放、关注、收藏、购买等控件；正常搜索可能更新 App 的搜索历史。
