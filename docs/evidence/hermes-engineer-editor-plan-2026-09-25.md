# Hermes Engineer 与项目 Editor 验收计划（运行前冻结）

## 范围与清理

在正式单节点环境，经管理员 API 建立两个临时空白项目 A/B 和一个随机密码的临时全局 `engineer` 账号；仅将该账号加入 A，项目角色为 `editor`。A/B 各建一条带不同标记的临时需求，A 使用现有已启用模型配置。密码只在运行进程内生成和使用，绝不输出、写盘或进入仓库。现存 Engineer 账号与定时 canary 账号均不修改。验收完成后撤销临时成员关系、停用临时账号、删除 A/B 并回查关联需求/计划/会话。用户管理 API 无删除入口，停用账号会作为不可登录的审计身份留存，须在报告中明确。

## 事前判据

| 编号 | 操作 | 预期 |
| --- | --- | --- |
| E01 | 临时账号登录并读取 A，管理员回查成员 | 全局角色 `engineer`、A 项目角色 `editor`，读取 HTTP 200 |
| E02 | Engineer 在 A 查询唯一需求标记 | HTTP 200、`llm_grounded`、仅 A 来源及有效 `[S1]`；标记正确，已知凭据/Token 不回显 |
| E03 | Engineer 在自己的 A 会话创建 Hermes `test_plan` 草稿并确认 | 创建与确认成功；生成的计划属于 A、状态 `draft`、`is_enabled=false`、手工调度，不自动运行 |
| E04 | Engineer 在 A 添加项目成员、删除项目 | 两项均 HTTP 403；A 的 `access_denied` 增加至少 2 条，按该用户/A 归属 |
| E05 | Engineer 在未授权 B 调用项目读取、Hermes 查询/编排/工具及草稿 | 五项均 HTTP 403；B 的拒绝审计增加至少 5 条，不返回 B 的来源/工具证据 |
| E06 | 管理员尝试确认 Engineer 的另一个待处理草稿 | HTTP 404；A 的工程师会话仅该用户可操作 |
| E07 | 管理员把 A 的成员角色降为 `viewer` 后，Engineer 再读 A 并新建草稿 | 读取 HTTP 200、新建草稿 HTTP 403，拒绝审计增加 |
| E08 | 管理员移除成员后，Engineer 再查询 A | HTTP 403，拒绝审计增加；管理员仍可读 A |
| E09 | 管理员停用临时 Engineer 后重试登录及旧 Token | 登录 HTTP 403、旧 Token 访问 HTTP 401；管理员回查账号为 `is_active=false` |
| E10 | 删除 A/B，回查临时项目、需求、计划和会话；读取项目 77 | 临时项目/需求/计划为 404，会话列表为 0；项目 77 为 200 且模型绑定前后相同，拒绝与工具审计按策略留存 |

十项全通过，且无跨项目来源、跨用户写入、错误审计归属、凭据回显、自动运行或可登录残留账号，才算本次有界验收通过。任一清理失败标记为阻塞。报告只保存状态码、实体 ID、布尔值和审计数量，不保存问题/回答正文、密码、Token、Cookie 或供应商密钥。本计划不替代供应商账单、业务内容质量、跨节点或 P4/P9 验收。
