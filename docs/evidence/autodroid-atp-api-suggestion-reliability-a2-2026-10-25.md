# A2 接口调试与建议可靠性

日期：2026-10-25。状态：代码与定向验证完成；真实业务接口和模型配置验收待补。

## 实现

- API 场景工作台在当前步骤调试得到响应后，才允许生成并审阅断言和取值建议。建议与步骤草稿、所选环境和响应对象绑定；发生变化后不能应用旧建议。
- 应用建议时跳过重复或当前编辑器不支持的规则，使用缓存响应重新计算断言结果；不会再次调用业务请求预览接口。AI 未配置时沿用现有规则建议。
- 建议接口按项目执行访问检查；向模型发送的 URL 和响应预览沿用 `redact_llm_text` 脱敏。模型返回的断言和取值路径必须在本次响应上成立，否则剔除并回退到规则建议。

- `npx vitest run src/views/workbench/ApiWorkbenchView.spec.ts --silent`：16 passed，覆盖重复应用、无二次业务请求、草稿变化后的失效，以及响应体较长时的全文校验。
- `npm run type-check`：通过。

## 限制

- 工作台目前只应用编辑器已有能力支持的断言与 JSONPath/响应头提取；不支持的 AI 建议被跳过。
- 需要在真实项目用只读 GET 和有写入副作用的 POST 各走一遍调试、建议、应用与报告；测试桩不能证明外部 API 或模型服务可用。
