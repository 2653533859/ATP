## 1. 版本概述 (Executive Summary)

ATP v2.7.0 是自动化测试平台迈向**跨端设备云化、微服务分布式追踪、可视化低代码工作流画布与企业级安全合规**的里程碑正式发布版本。

本版本历经 4 大阶段共 12 项重大特性演进，全面落地了 **iOS 移动真机池化与 W3C/XCUITest 自动化自愈**、**全链路分布式 TraceContext 注入与 Jaeger 慢调用拓扑下钻**、**多端多协议可视化流程图 DAG 编排与单步断点调试器**，以及 **PII 个人隐私数据保形脱敏网关、API Key 租户凭据细粒度治理与核心资产灾备恢复演练**。

## 2. 核心特性发布清单 (Key Highlights by Phase)

### Phase 1：iOS 移动真机池化与 W3C 自动化调度 (iOS Device Automation)

- **T1.1 iOS 统一设备资产与在线心跳模型**：
  - 落地 `ios_device_manager` 服务，基于 UDID 实现设备注册与活跃心跳自愈刷新；
  - 建立统一抽象模型 `UnifiedDeviceOut`，在 `GET /api/v1/devices/unified` 中整合 Android（`serial`）与 iOS（`udid`, `wda_local_port`, `appium_server_url`）集中设备池资产。
- **T1.2 W3C/Appium 2 XCUITest 会话自愈与租约队列**：
  - 建立 iOS 设备池行锁抢占算法（`acquire_available_ios_device_from_pool`），自动跳过忙碌占用或离线设备；
  - 落地 `handle_ios_device_disconnection_recovery`：设备掉线时自动释放租约并收敛在途执行为失败终态；
  - 落地 `ios_wda_session_healer`：精准识别 WDA 进程崩溃特征并自动重建 W3C 会话，保障自动化测试高可用。
- **T1.3 IPA 资产解析与低代码步骤执行**：
  - 落地 `ipa_parser` 服务，零代码执行安全提取 `Info.plist` 中的 Bundle ID、版本、支持设备等元数据；
  - `ios_executor` 原生支持点击、输入、滑动（精确四相指针控制）、断言与等待低代码操作，全面联动 WDA 崩溃自愈与录屏归档。

---

### Phase 2：全链路分布式 Trace 追踪与微服务下钻 (Distributed Tracing & APM)

- **T2.1 W3C TraceContext 与 traceparent 协议自动注入**：
  - 在 `app.core.tracing` 落地 W3C 标准 `traceparent`（`00-{trace_id}-{span_id}-01`）与 `tracestate` 生成算法；
  - 全面打通 HTTP/REST、GraphQL、gRPC 与多协议流水线执行器出站请求自动注入，贯通测试用例与后端微服务调用链。
- **T2.2 OpenTelemetry / Jaeger 分布式调用链检索**：
  - 落地 `apm_trace_retriever` 服务，检索 Jaeger HTTP API 并递归构建多级分层 Span 瀑布树；
  - 自动计算相对时间偏移量（`start_time_offset_ms`）与微秒级执行耗时，聚合微服务拓扑资产；
  - 开放专属瀑布图端点 `GET /api/v1/traces/{trace_id}/waterfall`。
- **T2.3 失败步骤慢调用瓶颈与异常 Span 自动标红聚类**：
  - 落地 `trace_anomaly_clustering` 服务，多维检测慢 SQL（>=100ms）、下游 5xx 故障、RPC 超时与慢服务调用；
  - 递归推导首要根因节点：提取 `root_cause_service`、`root_cause_span` 与高可读的中文根因诊断摘要，实现链路视图自动标红高亮。

---

### Phase 3：多端多协议混合低代码可视化编排画布 (Visual Workflow Canvas)

- **T3.1 多端多协议混合编排流程图引擎**：
  - 落地 `workflow_dag_engine` 服务，实现基于卡恩算法（Kahn's Algorithm）的线性拓扑排序与严格环路检测；
  - 调度器支持 `http`、`sql`、`redis`、`mobile`（Android/iOS）、`delay` 异构节点混合异步执行；
  - 开放 `POST /api/v1/api-scenarios/validate-dag` 与 `POST /api/v1/api-scenarios/execute-dag` 端点。
- **T3.2 节点间上下文变量双向数据流拓扑校验**：
  - 落地 `workflow_dataflow_validator` 服务，基于 DAG 祖先传递闭包分析变量可达性；
  - 静态拦截未声明引用的幽灵变量与下游逆向引用，构建变量血缘拓扑（`producer` $\rightarrow$ `consumers`）；
  - 开放 `POST /api/v1/api-scenarios/validate-dataflow` 端点。
- **T3.3 画布单步断点调试与实时数据流观察器**：
  - 落地 `workflow_debugger` 状态机服务，支持在画布节点配置断点；
  - 支持单步步过（`step_over`）、恢复运行（`resume`）与执行异常中断保护；
  - 实现实时数据流变量监视器（`watchers`）与 `context_diff` 前后上下文差分追踪；
  - 开放 `POST /api/v1/api-scenarios/debug/*` 全生命周期调试端点。

---

### Phase 4：企业级安全风控与合规审计增强 (Security & Compliance Governance)

- **T4.1 敏感测试数据与测试凭据动态脱敏网关**：
  - 落地 `sensitive_data_redactor` 服务，精准识别并保形脱敏 11 位手机号、18 位身份证、16-19 位银行卡、电子邮箱及企业自定义敏感词；
  - 递归遮蔽 `password`、`secret`、`api_token` 等凭证键名为 `******`；
  - 采用安全深拷贝零副作用设计，开放 `POST /api/v1/security/mask-pii` 端点。
- **T4.2 API Key / 租户令牌细粒度权限管控与审计导出**：
  - 设计 `ApiKey` 数据模型与 `20261015_0081` 迁移，SHA-256 安全哈希存证；
  - 支持单 IP 与 CIDR 子网掩码白名单安全校验、到期自动拦截与调用频次原子递增；
  - 全局认证中间件 `deps.py` 接入 `X-ATP-Api-Key` 请求头直连认证；
  - 开放 `POST /api/v1/security/api-keys` 与 `GET /api/v1/security/api-keys/audit-report` 审计报表导出。
- **T4.3 平台核心资产定时快照备份与灾备恢复演练**：
  - 落地 `disaster_recovery` 引擎，将核心数据库转储、产物元数据与带 SHA-256 哈希的 `manifest.json` 打包为 `tar.gz` 灾备归档；
  - 实现免停机沙箱化恢复演练（`perform_disaster_recovery_drill`），严格校验文件哈希防篡改与实体表数量对账；
  - 开放 `POST /api/v1/security/disaster-recovery/snapshot` 与 `drill` 演练端点。
