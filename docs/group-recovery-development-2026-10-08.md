# 执行状态、取消与恢复（N1.5，2026-10-08）

## 本批实现

承接 [N1.4 首次接受](suite-delivery-development-2026-10-08.md)，为套件和计划提供两种模式共用的状态解释及协作取消。投递、接受、租约和业务终态分别展示；读取状态不会重投、启动任务或清除接受凭据。

| 部分 | 已接入 |
| --- | --- |
| 只读查询 | `GET /api/v1/execution-groups/{suite\|plan}/{run_id}`，项目 viewer 权限；返回运行、取消请求、投递、接受时间、租约及子任务身份状态 |
| 取消请求 | `POST /api/v1/execution-groups/{suite\|plan}/{run_id}/cancel`，项目 editor 权限；必须携带查询结果的 expected_revision，身份变化返回 409 |
| 排队取消 | 同一事务按 UUID/pending 条件转 error 并记录取消时间，当前 Worker 的 pending→running 条件启动会拒绝继续执行 |
| 运行中取消 | 只持久记录请求，当前子任务/并发批次继续结束，后续子任务不再启动；不强制终止已有外部操作 |
| 取消重放 | 时间使用 coalesce 保留首个请求；已记录取消的重复提交不新增执行或取消副作用；未取消且已结束返回 409 |
| 前端入口 | 套件/计划执行记录展开后显示“执行状态与恢复”；提供刷新和明确语义的取消确认，关闭窗口后停止轮询 |
| 子运行归属 | 新建子运行后 flush，在首次执行/投递前，同事务保存 group_run_children；并发子任务独立写行，不争抢共享 JSON 归属记录 |
| 本地重启 | 只处理与当前父 UUID及持久子身份匹配的中断运行；无身份依据的旧 JSON 子引用不再按当前编号猜测恢复 |
| 计划保护 | PlanRun 增加 UUID；计划条件启动及租约恢复核对 UUID，保留终态；旧计划租约无 UUID 时不推断归属 |

查询使用父项目权限，并核对子任务的当前项目。已删除、身份变化或移动到其他项目的子任务显示身份待核对，不返回替代资源的状态。前端取消确认保存当时的身份版本；切换记录时不使用先前查询结果。

## 状态解释与处理

- 等待首次投递、投递中、已入队和已接受尚未开始分别显示。
- 发布结果不明确、投递受阻/未继续、接受后超过 5 分钟仍 pending，提示核对。五分钟仅用于状态说明，不触发重新接受或运行。
- running 需存在同 UUID 有效租约；计划内联套件可使用同项目、同父 UUID 的计划租约。缺少有效归属时提示核对，而不是据 running 声称 Worker 在线。
- 本地中断/异常队列以及服务器已到期租约提示检查外部副作用。父运行有终态但已记录子任务仍活跃时，提示单独核对。
- 子任务即使已写入终态，仍有 active/expired 执行租约时也提示核对，避免把超时写 error 当成外部执行已结束。
- 子任务查询展示前 200 条，并显示总数和截断说明；不把这个上限内的查询当作全部子任务已验收。旧 JSON 引用无持久身份记录时单独说明，禁止自动归属推断。
- 人工核对入口提供原运行、接受/租约和子任务状态；操作人员先检查报告、设备或外部目标，再决定是否显式创建新的运行。本批没有提供“标记成功”或未知结果自动重试按钮。

取消保持现有业务枚举：排队取消及协作停止的父运行最终为 error，并保留取消请求时间和说明；并非新增 cancelled 枚举或证明外部副作用不存在。计划取消等待当前套件/批次结束，不向全部子用例强制广播终止。

## 子任务记录与汇总

父套件/计划与子套件使用 UUID；子用例沿用 run_id＋原始 created_at 的队列身份约定。SQLite 保存原始时间字符串，PostgreSQL 时间统一到 UTC；本批没有为所有 TestRun 扩展 UUID或把全部入口改为持久投递。正常本地编号分配继续使用既有递增分配器。

本地恢复只从新归属表处理套件/计划子运行，不为旧 JSON 回填推断身份。参数化用例内部子树继续使用既有逻辑，不能把本批结论扩大到所有子执行类型。数据库旧快照恢复或服务器旧消息仍须先停止并核对执行流量。

并发批次已经全部完成后，即使某项触发快速失败，也汇总该批次每一条结果，再停止后续批次；取消的子用例计入 error，防止被汇总为通过。专用 Worker 子用例等待识别 cancelled 终态，不继续等到超时。
