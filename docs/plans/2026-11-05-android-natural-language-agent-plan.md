创建日期：2026-11-05；细化日期：2026-11-06
状态：M0 进行中；已新增协议/解析/预检原型，完整功能尚未实现或真机验证。代码核对基线：`eb1eddc4`。进展见[首批实现记录](../evidence/android-agent-m0-start-2026-11-06.md)。

实施入口：[Android 自然语言自动化实施清单与接口契约](2026-11-06-android-agent-implementation-backlog.md)。该清单细化本计划的 M0–M4，包含任务依赖、代码落点、状态与接口、数据库约束、预算、回放规则及交付门槛。字段、接口及默认值均是待实现设计，不代表现有功能。

## 1. 目标与范围

用户选择项目、Android 设备、目标 App 和测试数据，用自然语言描述操作与预期结果。Agent 在设备上逐步观察、执行和验证，记录完整轨迹；完成后整理为可编辑的 ATP Android 低代码用例草稿，并从约定初始状态独立回放。草稿经回放验证后，用户可将其保存为正式用例。

首版假设：Windows 本地模式、单用户、单设备、单 App，使用可重置的测试环境和具备视觉能力的已配置模型。Android 真机与模拟器都需验证，但不能假定结果一致。首版交付 ATP 用例步骤；独立 Python/Appium 脚本导出列为后续能力。

首版不承诺：任意 App 通用成功、iOS、多设备并发、无人处理验证码和系统认证、自动绕过安全限制、直接操作未授权的生产数据。

## 2. 用户流程与产物

1. 在 APP 工作台选择项目、设备、App、模型与参数，填写目标、初始状态和可观察的成功条件。缺少可判定的成功条件时要求补充，或将结果标记为待人工确认。
2. 预检设备状态、租约、App、模型、数据和敏感操作策略；展示外部模型会接收的数据范围。
3. 启动后显示设备画面、当前动作、每步结果及进度，可暂停、接管、恢复或终止。
4. Agent 每次基于当前观察提出一个结构化动作；执行器校验并执行，再读取新状态判定结果。遇到验证码、不可观察页面、危险动作或无法继续时暂停或停止。
5. 完整保留成功、失败、纠正与人工操作轨迹。生成器根据证据形成用例草稿；有未解决依赖、无法表达的步骤或缺失断言时明确标记，不得标为自动可回放。
6. 用户检查初始状态和数据后，从约定状态独立回放草稿。回放结果和草稿版本绑定，修改后验证状态失效。
7. 用户决定保存草稿为正式 Android 用例；正式用例走现有权限、编辑、执行、报告链路。

**成功的区分**：探索完成 ≠ 草稿生成成功 ≠ 自动回放通过 ≠ 业务结果正确。每个状态独立记录和展示。一次回放通过仅证明指定设备、App 版本、数据和初始状态下的结果。

## 3. 现状与必须补齐的基础

- `frontend/src/views/workbench/AppWorkbenchView.vue` 已有项目、设备、租约、预览和录制草稿入口；`frontend/src/views/case/AndroidCaseDrawer.vue` 承载 Android 用例编辑。
- `backend/app/api/v1/device_mirror.py` 和 `backend/app/worker/tasks_device.py` 有截图、点击、滑动、按键、输入和按点查询控件；目前按点查询不等同于可供 Agent 消费的完整标准化界面树，需要新增采集接口并测试。
- `backend/app/worker/executors/android_lowcode_executor.py` 读取 `config.steps`，已有启动 App、点击、输入、滑动、等待和断言。当前点击在控件定位失败时会回退原坐标；Agent 草稿需要安全的、可验证的回退策略。当前 `assert_text`/`assert_element` 基于 dump 字符串包含判断，应补充非空参数校验和结构化精确匹配，避免空字符串假通过。
- 当前文本输入最终调用 `adb shell input text`；中文、特殊字符、焦点及敏感输入的可靠性需要真机验证并补齐，不能依据注释假定已支持。
- `backend/app/services/ai_case/llm_client.py` 的非流式请求支持单张图片，但现有接口不等于完整 Agent、多轮消息或结构化工具调用；需做模型兼容性与能力预检。
- `backend/app/services/device_leases.py` 提供租约、心跳和释放；Agent、人工接管、重放必须共用同一独占控制约束。
- 仓库 `backend/app/core/local_schema.py` 当前本地 SQLite schema 版本为 18；`docs/windows-standalone.md` 中记录的 14 已滞后。实施时以实际代码和当前 Alembic head 为准，同时规划 SQLite 本地版本迁移和服务端 Alembic 迁移。

## 4. 技术方案

```text
APP 工作台：任务配置 / 实时画面 / 轨迹 / 草稿 / 回放
        │ 项目权限、租约、状态与事件
        ▼
Agent 会话服务：状态机、预算、持久化、恢复与人工接管
        │
        ├─ 观察：截图 + 标准化 UI 树 + 前台 App + 设备状态
        ├─ 决策：模型输出一个受限 JSON 动作与预期
        ├─ 安全校验：动作白名单、作用域、目标、坐标、预算
        ├─ 执行：本机设备适配器 → ADB / 现有设备控制
        ├─ 验证：等待条件 + 结构化断言 + 前后状态
        └─ 轨迹：追加式事件、脱敏证据、失败与接管标记
                         │
                         ▼
           草稿编译与检查 → 人工审阅 → 现有执行器独立回放
```

### 4.1 模型动作契约

模型仅能输出受限结构，例如 `action`、`target`、`arguments`、`expected_observation`、`reason`；经 Pydantic 严格校验后执行。首版允许 `tap`、`swipe`、`input`、`back`、`wait`、`finish` 和 `request_help`，不允许生成 shell、任意代码或任意设备命令。目标可含控件稳定属性和候选坐标；执行前重新确认页面、目标唯一性和坐标边界。连续失败、相同状态反复出现、低置信度或超预算时暂停，不无限重试。

UI 文本、截图和第三方页面均为不可信数据：只作为观察输入，不能覆盖系统规则、扩展动作范围或批准自身操作。模型报告完成只能作为建议，必须由独立成功条件检查确认。

### 4.2 控制权和状态机

会话状态建议：`created → prechecking → running ↔ paused → completed/failed/cancelled`，生成与回放状态独立管理。转移必须原子化并记录操作者和原因；终态不可隐式重启。

- 一次会话只持有一个设备租约；租约由会话协调器持有并续期，执行器每次写操作验证有效租约。暂停时是否继续持有设有明确超时，超时释放并要求重新获取。
- 人工接管属于同一会话下控制权从 Agent 转给用户，原 Agent 必须停止发动作；人工完成后重新采集状态并显式恢复。用户主动结束或接管超时均有清理路径。
- 命令有会话 ID、单调序号与幂等键。发送后超时或 Worker 崩溃造成执行结果未知时，标记 `outcome_unknown`、暂停并重采集；禁止自动重发有副作用的点击/输入。
- 取消、掉线、租约失效、进程重启均停止新动作，保留最后证据、收敛状态并释放或回收租约；已发出的动作不能假定撤销。前端断线重连从服务端事件序号恢复。
- 首版只接 Windows 本机设备适配器；不声称直接兼容远程 Agent。后续适配 Android Worker/远程通道时，必须验证租约、操作幂等与事件语义一致。

### 4.3 轨迹与草稿编译

每步保存：动作序号、观察前后引用、结构化目标、动作、参数占位符、执行状态、预期与验证结果、时间、App/设备环境、人工接管和失败原因。截图和 UI 树按项目权限管控并设置保留期；先脱敏再上传或发送到模型，若无法保证敏感内容安全则阻断云端发送或要求用户处理。

轨迹是事实日志，草稿是从轨迹生成的候选程序：保留纠错链；只有在证明后续步骤不依赖失败操作的状态时才可消除动作。将输入值参数化，密码只保留变量引用；生成必要断言、可执行的等待和初始状态说明。当前执行器主要是固定等待，需增加有超时的条件等待或显式标记限制。坐标回退仅在页面签名、屏幕方向/尺寸等条件满足并验证目标时可使用；否则暂停，不盲点。无法自动表达的人工步骤明确标记并阻止自动回放通过。

### 4.4 数据模型与接口草案

新增持久化概念（具体表名和字段在实现前以迁移评审为准）：`AgentSession`（项目、设备、用户、目标、状态、预算、租约、环境）、`AgentStepEvent`（有序事件、证据引用、执行结果）、`AgentDraft`（草稿版本、生成来源、校验状态、回放 run ID）。不保存明文密钥、密码或租约令牌到事件和日志；签名 URL 不作为永久证据地址。草稿关联现有用例及回放结果，删除和归档遵循项目现有策略。

建议接口：创建会话、查询会话与分页事件、暂停/接管/恢复/取消、生成草稿、查看或更新草稿、发起回放、保存正式用例；进度可通过现有事件机制或轮询提供。所有接口校验登录、项目权限、设备权限与会话归属；状态变更使用版本号或条件更新防止并发覆盖。具体 URI、事件通道和本地队列复用方式在 M0 技术验证后确定，避免在未核实的执行路径上承诺接口。

### 4.5 方案取舍

首选复用 ATP 的设备控制、低代码步骤、项目权限和报告，新增受限 Agent 层；好处是草稿可编辑、可融入已有用例流程，代价是需自行实现观察、闭环和录制可靠性。备选是接入现成移动 Agent 框架：可缩短探索原型，但需评估依赖、设备助手、许可、Windows 与远程执行、数据安全及轨迹转 ATP 步骤的成本。M0 用同一批任务对比，若自研路径明显无法达到验收阈值或维护成本过高，再重新评估；不在未做 POC 时承诺框架性能。

## 5. 分阶段工作与验收

以下工期为单名熟悉 ATP 的全栈开发者粗估，依赖可用测试设备、测试 App、测试账号和可用视觉模型；不含等待外部资源、重大历史问题或生产验收。各阶段依赖前一阶段结果，先完成 M0 再校准后续时间。

| 阶段 | 预计 | 主要工作 | 交付与退出条件 |
| --- | --- | --- | --- |
| M0 可行性验证 | 3–5 人日 | 固定设备、模型和 3–5 个可重置场景；测截图/完整 UI 树、中文输入、元素唯一性、租约和模型结构化输出；记录成本与耗时；比较候选框架 | 有可复现的演示和结果清单；确认本机执行链、数据边界与不能支持的场景；给后续阶段重新估时 |
| M1 设备与安全基础 | 5–8 人日 | 标准化观察；受限动作执行与权限、租约、预算；可靠输入、结构化断言、条件等待、坐标回退保护；单步结果和未知结果处理 | 在测试 App 验证各基本动作及异常；设备独占、取消、失联和敏感数据测试通过 |
| M2 Agent 与轨迹 | 6–10 人日 | 会话状态机、模型适配、逐步观察执行校验、持久化事件、暂停/接管/恢复、重连；SQLite 与 Alembic 迁移 | 至少完成一条真实探索并留存可核验证据；失败、重启和租约失效有明确终态，不重复执行未知动作 |
| M3 草稿与独立回放 | 5–8 人日 | 轨迹转 `config.steps`、参数化和断言、草稿编辑、环境重置约定、独立执行及结果绑定 | 指定场景探索完成后可编辑并重置回放；不能转换或依赖人工的步骤明确标记；修改草稿使旧回放失效 |
| M4 工作台与试点 | 5–8 人日 | 工作台完整流程、权限/敏感数据提示、进度、成本与错误展示；固定任务集验收和文档 | 完成端到端试点与指标统计，输出已支持场景和失败边界；仅在达到验收条件后逐步开放 |

合计约 **24–39 人日**，是范围估计，不代表已验证的承诺；可在 M0 结束后重新拆分与报价。M1 的基础能力与 M2 的开发可以在契约明确后并行，但以上总量按工作量而非日历周期计算。

## 6. 测试与验收口径

### 功能和效果

选定不少于 10 个任务，覆盖启动、导航、搜索/输入、列表选择、断言、可控弹窗与失败处理；至少 2 个测试 App，明确 Android 版本、设备、App 版本、初始状态与可重复重置方法。每个场景重复至少 3 次，并分别统计：

- **探索成功率**：满足独立可观察成功条件的探索次数 / 全部探索次数，人工接管次数单列。
- **草稿生成率**：生成结构合法、无未解决人工步骤的草稿次数 / 全部探索次数。
- **独立回放通过率**：从预先声明并验证的初始状态，无 Agent 和人工介入通过业务断言的回放次数 / 发起的回放次数。
- 另记录误操作、错误断言、平均与 P95 耗时、模型请求次数/成本、失败分类和设备/模型版本。未完成和中断都计入相应分母并标记原因。

试点目标建议：固定测试集探索成功率 ≥80%，可自动回放草稿的独立回放通过率 ≥90%，危险动作未授权执行 0 次，错误成功判定 0 次；样本小只作为试点门槛，不代表统计意义上的生产可靠性。首轮若未达标，保留结果并针对主要失败原因迭代，不调整分母掩盖失败。

### 工程验证

- 后端：状态转换、权限隔离、动作白名单、提示注入、敏感值脱敏、超时与取消、设备锁竞争、未知执行结果、恢复和迁移；关键失败新增可单文件运行的回归测试。
- 前端：任务表单、进度、暂停接管、断线重连、草稿编辑、回放状态失效和错误信息。
- 系统：模拟器与真机分别验证，包括 App 冷启动/热启动、页面加载延迟、不同分辨率、中文/特殊字符、定位歧义、系统弹窗和 `FLAG_SECURE` 无法截图场景。
- 迁移：空库及旧库升级、备份恢复；SQLite 本地版本迁移和 Alembic 分别验证，PostgreSQL 上执行真实迁移验证，不用 SQLite 结果代替。
- 常规检查按仓库 Makefile 和改动范围执行；不能完成全量、远程设备或生产验收时明确披露，不将局部测试称为全量通过。

## 7. 风险、发布与回退

1. **隐私与模型外发**：默认只在用户已知且允许的数据范围内发送；账号、验证码、密码与敏感页面采用脱敏或暂停，限制访问与保存时间。
2. **误操作与外部副作用**：测试环境和明确目标 App 优先；删除、支付、发布、发送等动作必须按策略确认。系统不知道结果时停止，不重复点击。
3. **设备隔离与恢复**：全链路复用设备租约；进程、前端、设备断开和重启均有状态与租约恢复测试。
4. **回放失真**：记录环境、前置条件和数据，保留全部轨迹，草稿版本与回放结果绑定，避免把探索偶然成功当作稳定脚本。
5. **灰度与回退**：以独立功能开关按项目或环境开放；关闭后停止创建新会话，运行中会话安全停止并留存证据，现有 Android 用例不受影响。数据库迁移按可回退策略设计；回退前备份并明确数据保留与版本兼容，禁止通过回滚删除未备份用户数据。

## 8. 需要在 M0 确定的产品选择

- 目标 App、Android 机型和能否提供可重复重置的测试账号与数据。
- AI 模型部署与数据边界：外部服务、本地模型或两者可选；确认图片是否允许离开本机。
- 脚本交付形式：首版默认 ATP 低代码用例；如必须交付独立 Appium/Python 文件，将导出器、运行依赖和独立验证纳入首版范围并重新估时。
- 验收成功条件的来源：用户显式定义、从任务中提取后人工确认，或已有业务测试数据；不能由模型单方面宣布成功。
