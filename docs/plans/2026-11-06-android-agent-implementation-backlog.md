## 1. 首版做成什么

入口放在现有 APP 工作台的“自然语言任务”页签。用户选择设备、已安装的目标 App、视觉模型，填写目标和成功条件。ATP 自动观察设备、逐步操作；用户可暂停、接管和结束。结束后生成 Android 低代码草稿，用户编辑并从指定初始状态独立回放，再保存为正式用例。

演示任务采用可重置的测试 App，例如：“打开测试商城，搜索测试商品，进入详情页，确认商品名称和库存状态”。不把任意第三方商城或生产账号作为默认测试环境。

一次合格演示必须交付：

1. 用户确认的目标、成功条件和初始状态。
2. 每次观察、动作、验证和失败的有序轨迹。
3. 可编辑的 `TestCase.config.steps` 候选草稿及来源映射。
4. 与草稿版本绑定的独立回放结果；探索过程不能充当回放。
5. 保存后的正式用例 ID，以及适用的设备、App 版本和限制。

首版限定 Windows 本地独立模式、同时一个 Agent 会话、一台设备和一个目标 App；设备可经 USB 或局域网 ADB 连接。单设备仍必须与既有用例执行和人工投屏互斥。Linux 云端可继续提供现有服务，但本阶段不新增云端发起 Agent、远程节点执行、轨迹跨端同步或独立 Python/Appium 导出。

## 3. 使用流程与页面行为

| 页面区域 | 输入或展示 | 验收要求 |
| --- | --- | --- |
| 任务配置 | 项目、设备、App 包名、模型、目标、初始状态、测试数据引用、成功条件 | 成功条件不能为空；模型提取的条件必须由用户确认；设备占用、模型无视觉能力时禁止开始 |
| 预检结果 | ADB 连通、App 存在、截图/UI 树能力、输入方式、模型探测、租约、数据外发范围 | 分清阻断项和降级项；未检测成功不能显示“已就绪” |
| 实时执行 | 设备画面、当前动作、结果、剩余步数/时间、模型用量 | 标注观察时间和画面失效状态；模型理由只是解释，不能作为成功证据 |
| 控制栏 | 暂停、接管、恢复、取消 | 显示请求中与已生效的区别；接管生效前禁止手动写操作 |
| 轨迹列表 | 观察前后、动作、验证结果、错误、人工操作 | 按事件序号恢复，刷新后不丢失；敏感内容不可从详情泄漏 |
| 草稿审阅 | 低代码步骤、变量引用、断言、来源、不能自动转换项 | 未解决项影响可回放状态；修改后旧验证结果立即失效 |
| 回放与保存 | 初始状态核对、独立运行 ID、断言结果、保存按钮 | 默认仅当前版本回放通过才允许保存为正式用例；失败草稿仍可保留编辑 |

首次用户输入示例：“搜索商品并打开详情”需要补充商品变量与可验证的结果，例如“详情页商品名称等于 `${product_name}`”。模型只能提出条件候选，不能自行放宽用户确认的条件。

## 4. 后端模块与执行路径

拟新增以下模块，复用现有能力时从服务层调用，不在 Agent 内调用 HTTP 路由函数：

| 模块 | 职责 |
| --- | --- |
| `backend/app/models/android_agent.py` | 会话、事件、动作命令、草稿、回放绑定 |
| `backend/app/schemas/android_agent.py` | 输入、输出、动作联合类型、错误码、契约版本 |
| `backend/app/api/v1/android_agent.py` | 权限、版本和幂等校验，控制与查询 API |
| `backend/app/services/android_agent/observation.py` | 截图、完整 UI 树、前台包名、方向/尺寸、一致性检查和脱敏 |
| `backend/app/services/android_agent/device_adapter.py` | 本机 ADB 适配与写操作门禁；不能从模型接收 shell 命令 |
| `backend/app/services/android_agent/model_adapter.py` | 有限观察历史、模型请求、结构校验、用量提取 |
| `backend/app/services/android_agent/policy.py` | App 边界、动作白名单、敏感页面、预算和目标唯一性 |
| `backend/app/services/android_agent/coordinator.py` | 持久状态、单步调度、控制指令、进程恢复和租约续期 |
| `backend/app/services/android_agent/compiler.py` | 轨迹到草稿的可追溯转换，不直接执行模型生成代码 |
| `backend/app/services/android_agent/replay.py` | 草稿快照、独立运行、验证绑定及保存正式用例 |
| `frontend/src/api/androidAgent.ts`、工作台子组件 | 会话 API、表单、控制栏、事件列表与草稿状态 |

协调器每轮只处理一次观察和一个候选动作：读取状态与预算 → 获取观察 → 请求模型 → 校验动作 → 再查控制代次和租约 → 记录命令准备状态 → 串行执行 → 采集后状态 → 独立验证 → 事务写结果和事件 → 下一轮。

不持有数据库事务等待模型或 ADB。专用协调器不能只依赖内存线程：启动时需取得数据库协调器所有权/心跳，进程退出后旧所有权失效；并发启动第二个后端不得重复接管同一会话。跨进程独占实现及 SQLite 锁策略列入 M0 必测项。

回放复用现有 `TestRun` 和本地执行队列。M0 确认现有调度是否强制依赖已保存 `TestCase`；若需要临时用例，必须项目隔离、不可进入正常调度列表、与草稿快照绑定，运行结束后按保留策略处理。不能未经审阅提前创建可调度的正式用例。

## 5. 观察与模型动作契约

### 5.1 Observation v1

建议字段：`observation_id`、`session_id`、`captured_at`、`package_name`、`activity`（可为空）、`screen.width/height/rotation`、`screenshot_ref`、`ui_tree_ref`、`nodes`、`page_signature`、`capabilities`、`redactions`。

节点仅在当前观察内有稳定的 `node_id`，包含 `resource_id`、`text`、`content_desc`、`class_name`、`bounds`、`clickable`、`enabled`、`password`、父子关系。XML 使用安全解析器，限制大小与深度。不得把节点文本拼接为可执行指令。

截图和 UI 树不能假定同一时刻：记录采集时间差，前后检查包名、方向和页面特征；出现跳页则丢弃组合重新采集。UI 树不可用时标记原因，视觉模式不得谎称已经进行元素级确认。`FLAG_SECURE` 或脱敏不可判定时暂停，不尝试绕过截图保护。

### 5.2 Action v1

```json
{
  "schema_version": 1,
  "observation_id": "obs-0007",
  "action": "tap",
  "target": {"node_id": "n12"},
  "expected_observation": {
    "type": "element_visible",
    "resource_id": "com.example.test:id/search_input"
  },
  "reason": "打开搜索输入框"
}
```

服务端另行分配 `command_id`、`sequence`、`control_epoch`、幂等键和超时；模型不能指定身份、设备租约、项目或权限。

| 模型动作 | 输入约束 | 草稿映射 |
| --- | --- | --- |
| `tap` | 当前观察中的唯一目标；坐标必须显式标为受保护降级 | `click`，优先保存稳定选择器 |
| `input` | 输入目标及 `value_ref`；执行端解析授权变量 | `input`，保留变量引用，禁止写入密码明文 |
| `swipe` | 方向/区域/距离受限；必须在屏幕内 | `swipe`，保存原始坐标空间 |
| `back` | 白名单按键；后续包名仍需校验 | `press_key`，仅 back |
| `wait` | 可执行条件与有限超时 | 拟新增 `wait_until`；不冒充现有能力 |
| `finish` | 只能提出结束建议 | 不生成操作步骤；执行用户确认的终态断言 |
| `request_help` | 标准原因码和解释 | 暂停；未解决的人工依赖阻止自动回放通过 |

启动目标 App 由已验证的任务配置决定，生成固定 `start_app` 前置步骤。首版不允许模型任意切换包、安装 APK、调用 shell、修改系统设置或扩大任务范围。目标 App 内的敏感业务操作采用明确策略；系统权限弹窗等跨包操作默认请求人工处理。

模型响应按动作类型做严格联合校验，拒绝额外字段、越界坐标和不存在的节点。观察失效必须重采集；修复无效 JSON 至多一次且计入模型预算。即使供应商支持结构化输出，服务端仍需校验。

## 6. 控制权、状态和恢复

会话状态：`created → prechecking → running → completed/failed/cancelled`，另有 `pause_requested → paused`、`cancelling`；`paused` 可经预检回到 `running`。控制者单独用 `controller=agent/manual/none` 表达，避免把人工接管混入任务成功状态。

| 触发 | 状态和控制权规则 |
| --- | --- |
| 暂停 | 先持久化暂停请求并递增 `control_epoch`；旧模型响应失效；正在执行的 ADB 动作收敛后才显示 paused |
| 接管 | 先完成暂停屏障，再把 controller 改为 manual；手动操作同样记录并经过写门禁 |
| 恢复 | 重新确认权限、租约、前台 App、初始依赖和预算；采集新观察，不能沿用暂停前动作 |
| 取消 | 禁止新动作，进入 cancelling；已发送动作无法保证撤销，完成有界清理后终态 |
| 执行超时/进程异常 | 已准备发送但未确认结果的命令标记 `outcome_unknown`；暂停待核查，不自动重发点击/输入 |
| 后端重启 | 扫描非终态会话并收敛为恢复待确认；旧控制代次失效，禁止自动继续设备操作 |
| 租约/权限失效 | 不发新动作，记录原因并安全释放控制；恢复需重新获取授权和租约 |
| 前端断线 | 事件仍持久化；控制连接心跳超过约定时间后请求暂停，不因界面刷新而重建任务 |

设备写门禁应覆盖 Agent、投屏、低代码回放及其他设备写路径；仅在新 API 上检查租约仍可能被旧路径绕过。门禁内再次检查租约与代次，原子占用设备命令槽，结束后释放；取消先撤销后续命令资格，再等待当前命令收敛。SQLite 不以 `SELECT FOR UPDATE` 作为互斥保证，使用唯一约束和条件更新，并将冲突统一返回 409。

推荐的试点默认值（M0 校准，可在合理上限内调整）：

| 项目 | 默认值 | 超限行为 |
| --- | --- | --- |
| 单会话动作/模型调用 | 30 步 / 40 次 | 停止新动作，保留结果 |
| 单会话总时长 | 10 分钟，含暂停时间 | 结束并显示预算耗尽 |
| 单次模型请求 | 30 秒 | 一次只读重试，仍计入总预算 |
| 单次 ADB 命令/条件等待 | 10 秒 / 15 秒 | 观察超时可重试；写操作超时按未知结果处理 |
| 连续执行失败/重复无进展观察 | 2 次 / 3 次 | 暂停并给出原因 |
| 租约 TTL/续期周期 | 90 秒 / 20 秒 | 续期失败后拒绝后续写操作 |
| 暂停保留租约/前端心跳失联 | 120 秒 / 60 秒 | 释放租约 / 请求暂停 |
| 脱敏证据保留期 | 7 天，服从项目配置 | 清理对象但保留摘要和已过期标记 |

租约续期独立于模型请求。调用数与 token 用量落库；缺少供应商计价时只显示用量和“费用未知”，不能展示虚假的精确金额。配置金额上限时必须先有可核验计价。

## 7. 数据模型与事务约束

| 拟新增表 | 主要字段与约束 |
| --- | --- |
| `android_agent_sessions` | ID、project_id、device_id、created_by、目标、确认后的成功条件、包名、模型配置引用、状态、controller、version、control_epoch、预算/用量、环境快照、错误码和时间；不保存模型密钥 |
| `android_agent_events` | session_id、seq、event_type、脱敏 payload、artifact_refs、created_at；唯一 `(session_id, seq)`，游标分页；状态变更与事件同事务 |
| `android_agent_commands` | command_id、session_id、seq、control_epoch、observation_id、幂等键、请求哈希、prepared/executing/succeeded/failed/outcome_unknown、结果摘要；幂等键唯一，键复用但参数不同返回 409 |
| `android_agent_drafts` | session_id、version、steps、变量引用、前置条件、来源映射、未解决项、内容哈希、状态；唯一 `(session_id, version)`，每次编辑形成不可变版本 |
| `android_agent_replays` | draft_id/version/hash、环境/数据版本、run_id、状态和证据摘要；同版本进行中的回放不重复启动 |

创建会话的请求幂等记录与会话落库同事务；任务领取采用条件更新。数据库提交成功但执行未开始的崩溃，与执行完成但结果未提交的崩溃必须分别测试，不能宣称数据库事务能提供 ADB 的 exactly-once。

证据对象建议路径：`android-agent/projects/{project_id}/sessions/{session_id}/...`。保存对象键和摘要，不保存带过期签名的 URL。上传失败记录独立错误，不能伪造证据存在；孤儿对象按保留策略处理。读取、下载和删除都重新检查项目权限；不能通过猜对象键跨项目读取。

迁移需同时接入模型注册、SQLite 本地升级与 Alembic。先做新增表和兼容字段；回退应用时保留新增数据，功能关闭后再停止协调器，禁止为回退直接删会话表。

## 8. API v1 提案

统一前缀：`/api/v1/projects/{project_id}/android-agent`。会话只接受设备数据库 ID，不接收客户端任意 ADB 地址。轮询为首版进度传输方式，暂不增加 WebSocket 协议。

| 方法和相对路径 | 作用 | 主要约束 |
| --- | --- | --- |
| `POST /sessions` | 创建并排队预检，返回 201 | 目标、初始状态、成功条件、设备/App/模型、数据引用和预算；`Idempotency-Key` 必填 |
| `GET /sessions/{id}` | 会话状态与能力、用量 | 包含 version、last_event_seq，不返回租约令牌或密钥 |
| `GET /sessions/{id}/events?after_seq=N&limit=100` | 有序增量事件 | limit 上限 200；返回 next_seq；前端按 seq 去重并检测缺口 |
| `POST /sessions/{id}/control` | pause/takeover/resume/cancel | `expected_version`、幂等键、原因；异步动作返回 202，实际生效由状态确认 |
| `POST /sessions/{id}/manual-actions` | 接管后的人工动作 | 仅 controller=manual，服务端生成命令序号并检查同一租约 |
| `POST /sessions/{id}/drafts` | 编译新草稿版本 | 会话终态后允许；失败轨迹也可生成带阻断项的草稿 |
| `GET /drafts/{id}`、`PATCH /drafts/{id}` | 读取与编辑草稿 | 编辑带 expected_version，生成新版本并作废旧验证资格 |
| `POST /drafts/{id}/replays` | 发起独立回放 | 固定草稿版本/哈希；确认初始状态，重新获取设备租约 |
| `GET /replays/{id}` | 回放状态和运行入口 | 关联 TestRun；不能把轮询失败当成执行失败 |
| `POST /drafts/{id}/publish` | 保存正式用例 | 绑定当前验证版本、哈希和幂等键；重复请求返回同一用例 |

权限：项目 viewer 只读；创建、控制、编辑、回放、发布要求项目 editor，并满足现有设备控制角色要求。所有关联对象再次核对 project_id；API Key 也须核对作用域。会话控制限创建者或有权限的管理员接管，接管留审计。当前设备模型没有项目归属字段，M0 要明确设备访问策略；不能以“设备在线”或只有全局工程师角色替代授权。

建议错误码：`device_busy`、`model_capability_missing`、`observation_stale`、`target_ambiguous`、`lease_lost`、`permission_revoked`、`action_blocked`、`outcome_unknown`、`budget_exceeded`、`draft_not_replayable`、`version_conflict`。HTTP 使用 401/403/404/409/422/503 对应认证、权限、对象、冲突、校验和暂不可用；错误信息不能带原始输入、密钥或模型请求全文。

## 9. 草稿和回放的具体规则

1. 所有动作保留来源事件 ID；纠错尝试不能静默删除。无法证明可删除的探索步骤进入“待人工整理”。
2. 输入参数使用现有运行变量机制；敏感值由执行端按引用解析，不送给模型、不写草稿。M0 核对现有 Android 路径变量替换和脱敏，不能只复用前端占位文本。
3. 拟增加严格定位选项与 `wait_until`：选择器唯一匹配，按结构化属性精确判断；超时必须失败。旧用例兼容策略单独测试，不能全局关闭坐标能力导致存量回归。
4. 对新 Agent 草稿默认禁用盲目坐标回退；视觉降级必须匹配方向、尺寸、包名和目标附近特征，并在回放中独立验证。不能验证则阻断。
5. 终态断言来自用户确认条件。模型“finish”、网络请求成功或页面变化都不能单独说明业务目标成功。
6. 初始状态需可核对：App 版本、登录状态、页面位置、测试数据版本、必要权限。默认不自动清除 App 数据或卸载重装；环境重置方案由测试夹具提供或人工完成后核对。
7. 回放必须关闭 Agent 决策，仅由现有执行器执行固定快照；失败不能临时请模型修复后仍将原回放记为通过。
8. 编辑、重新编译、成功条件变化、测试数据版本变化会使验证资格失效。回放结果仅证明记录的环境；不声明跨设备兼容。
9. 录制轨迹默认保存截图和 UI 树；视频沿用现有 Android `record_video` 可选能力，不将“录制步骤”宣传为一定生成视频。

## 11. 试点验收矩阵与计数口径

固定 10 个任务，至少覆盖两个可控测试 App：启动到目标页、中文搜索、特殊字符输入、列表选中、详情属性断言、返回导航、滚动后定位、可控弹窗、重复名称歧义、目标不存在。失败场景的合格结果是正确失败或暂停，不能算“探索成功”；单独统计异常处理通过率。

成功场景和异常场景在测试前分别登记，不临时换题。每个任务在真机和模拟器各重复 3 次，至少 60 次探索尝试；以单次尝试记录，不把同一任务多次重试只计最终成功。两个环境分别报告，再给汇总结果。

| 维度 | 发布门槛或报告要求 |
| --- | --- |
| 成功任务探索 | 在预先声明可达成的任务集上 ≥80%；人工接管成功单列，不计自主探索成功 |
| 草稿产出 | 报告可回放草稿数/全部成功任务探索尝试数；建议门槛 ≥70%，M0 后冻结 |
| 独立回放 | 每个可回放草稿重置后回放 3 次，正确业务断言通过率 ≥90%；未完成、中断计入已发起的分母 |
| 全流程产出 | 另外报告通过回放的草稿数/全部成功任务探索尝试数，防止只挑少量好草稿美化回放率 |
| 异常处理 | 歧义、目标不存在、权限撤销、掉线、预算和模型非法输出均到达预期状态 |
| 控制正确性 | 重复动作、无权限操作、错误宣告成功均为 0；任何一次出现均阻断发布 |
| 成本与时延 | 记录模型/动作耗时、端到端耗时、调用数、token；P95 标注样本数和统计方式，M0 后才设性能阈值 |

必须覆盖故障注入点：模型请求中暂停、动作发送前取消、动作已执行但落库前进程退出、租约过期后旧模型返回、投屏和 Agent 同时点击、同幂等键重复启动、修改草稿时旧回放完成、事件断线重连、删除项目、模型响应夹带越权指令。真实设备副作用检查不能完全用 Mock 替代。

后端测试拟放 `backend/tests/services/test_android_agent_*.py`、`backend/tests/api/test_android_agent_*.py`；迁移测试放 `backend/tests/migrations/`；前端单测随组件，端到端放 `frontend/e2e/android-agent.spec.ts`。测试命令沿用 Makefile；Windows pytest 使用仓库内 basetemp。迁移分别验证 SQLite 旧数据副本和真实 PostgreSQL，不能相互替代。

## 12. 第一批执行顺序与待确认输入

第一批只启动 M0，不立即铺开全部页面和表结构：

1. 第 1 人日：固定设备、App、模型、数据外发边界与 5 个 POC 任务；记录每个任务初始状态和独立成功条件。

3. 第 3 人日：完成严格 JSON 的单步模型闭环、总预算和失败停止；测一次模型迟到响应被控制代次拒绝。
